# Contribuição

1. Leia `docs/REGRAS.md` e `docs/ARQUITETURA.md`.
2. Para mudanças grandes, abra issue com problema, objetivo, escopo, critérios de aceite, riscos e migração de dados quando aplicável.
3. Crie `feature/descricao`, `fix/descricao` ou `docs/descricao` a partir de `main`.
4. Faça alterações pequenas e rastreáveis. Documente decisões estruturais em `docs/decisions/`.
5. Execute `npm run check` e `npm run build`; atualize o `CHANGELOG.md` para mudanças visíveis ou estruturais.
6. Abra PR explicando o que mudou, por quê, como foi testado e o impacto. Não faça merge com verificações falhando.

Mensagens de commit: `feat(web): adiciona tema`, `fix(core): corrige permissão`, `docs(architecture): descreve workspaces`.
